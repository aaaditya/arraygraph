## What you will learn
- Why checking every locker is slow.
- How binary search cuts the range in half each time.
- The three pointers: low, mid and high.

## The story
<Analogy emoji='🔢' title='Guess my number'>
I pick a secret number from 1 to 100.
You may ask: "Is it 50?" I say higher or lower.
Each good guess throws away half the remaining numbers.
After about seven guesses you can pin any number up to 100.
Checking 1, then 2, then 3 would take up to 100 tries. That is linear search.
</Analogy>

A sorted row of lockers works the same way. Always open the middle locker first.

## Now the code
The array must already be sorted. Mid is the floor of (low + high) / 2.

<CodeTabs
python={`def binary_search(nums, target):
    low, high = 0, len(nums) - 1
    while low <= high:
        mid = (low + high) // 2
        if nums[mid] == target:
            return mid
        if nums[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1`}
javascript={`function binarySearch(nums, target) {
  let low = 0;
  let high = nums.length - 1;
  while (low <= high) {

    if (nums[mid] === target) return mid;
    if (nums[mid] < target) low = mid + 1;
    else high = mid - 1;
  }
  return -1;
}`}

## How fast is it?
<Complexity time='O(log n)' space='O(1)' why='Each step throws away half the remaining items, so we only need about log2(n) looks.' />

## Common mistakes
- Forgetting the array must be sorted first.
- Using `(low + high) / 2` in languages where that can overflow. Prefer `low + (high - low) / 2`.
- Writing `while low < high` and missing the last element. Use `<=` when both ends are inclusive.
- Updating `low = mid` instead of `mid + 1`, which can loop forever.

## Interview angle
<InterviewTip>
Interviewers listen for the word **sorted**. If the data is sorted, or you can sort the answer space, binary search is often the tool.
Follow-ups: first and last occurrence, search in a rotated array, and binary search on the answer (Koko eating bananas).
</InterviewTip>
