## What you will learn
- How `if` / `else` picks one path.
- How a traffic light maps to clear decisions.
- A tiny FizzBuzz-style choice based on a number.

## The story
<Analogy emoji="🚦" title="Traffic signal decisions">
At a crossing, you look at the light.
If it is **red**, you **stop**.
Else if it is **yellow**, you **wait**.
Else if it is **green**, you **go**.
You do not do all three. You pick one path.
**Conditions** in code work the same way.
The computer asks a yes/no question, then follows the matching branch.
</Analogy>

Without conditions, every program would do the same thing every time — like always crossing, even on red.

## Now the code
Here is the traffic decision, then a small number version called FizzBuzz lite.

<CodeTabs
python={`def traffic_action(color: str) -> str:
    if color == "red":
        return "stop"
    elif color == "yellow":
        return "wait"
    elif color == "green":
        return "go"
    else:
        return "unknown"

def fizzbuzz_lite(n: int) -> str:
    if n % 15 == 0:          # both 3 and 5
        return "FizzBuzz"
    if n % 3 == 0:
        return "Fizz"
    if n % 5 == 0:
        return "Buzz"
    return str(n)

print(traffic_action("green"))  # go
print(fizzbuzz_lite(15))        # FizzBuzz`}

## Common mistakes
- Forgetting `else` when you need a backup path.
- Checking divisible-by-3 before divisible-by-both, so 15 never says FizzBuzz.
- Using `=` (assign) when you meant `==` (compare) in some languages.

## Interview angle
<InterviewTip>
Interviewers love tiny decision problems.
Say the rules out loud before coding: "If red stop, else if yellow wait, else if green go."
That shows you can turn a story into clear branches.
For FizzBuzz, mention the both-3-and-5 case first.
</InterviewTip>
